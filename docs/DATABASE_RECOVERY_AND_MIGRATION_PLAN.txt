4. POST-MIGRATION INTEGRITY AND SECURITY VERIFICATION
--------------------------------------------------------------------------------
Execute the following verification queries in Supabase SQL Editor:

A. Confirm Row Level Security is active on 100% of public tables:
   SELECT tablename, rowsecurity
   FROM pg_tables
   WHERE schemaname = 'public'
   ORDER BY tablename;
   Invariant: Every table must have rowsecurity = true.

B. Verify Foreign Key Index Coverage:
   SELECT
       conrelid::regclass AS table_name,
       a.attname AS fk_column
   FROM pg_constraint c
   JOIN pg_attribute a ON a.attrelid = c.conrelid AND a.attnum = ANY(c.conkey)
   WHERE c.contype = 'f' AND c.connamespace = 'public'::regnamespace;

C. Execute Local Test Suite:
   node scripts/test_tenant_rls.mjs
   node scripts/test_tenant_isolation_adversarial.mjs
   Both suites must pass with exit code 0.


5. ROLLBACK AND DISASTER RECOVERY PROTOCOL
--------------------------------------------------------------------------------
1. Non-Destructive Forward Schema Principle:
   - All migrations are non-destructive and forward-only (additive column additions,
     indexes, and non-blocking constraints).
   - Never run 'DROP TABLE' or 'DROP SCHEMA CASCADE' in production.

2. Restoring from Snapshot Backup:
   - In Supabase Dashboard -> Database -> Backups.
   - Select the pre-migration snapshot taken in Phase 2.
   - Click "Restore" to re-instantiate the database state.
   - Cloudflare Pages Functions will automatically reconnect upon compute restoration.

3. Restoring via Point-in-Time Recovery (PITR):
   - Pro and Enterprise tiers allow restoring to any specific second within the retention window.
   - In Supabase Dashboard -> Database -> Backups -> PITR.
   - Select target timestamp preceding the defect.
   - Trigger restore to an isolated clone, verify data integrity, and update Cloudflare secrets.
